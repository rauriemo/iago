# Recorded wave evaluation

Run `uv run --extra vision --extra robot iago-verify --suite offline --select recorded_waves --output local-data/evidence/recorded-waves` after setting private `IAGO_WAVE_CLIP_MANIFEST` to the frozen manifest. The required check reports blocked without the real recordings or installed vision models. It is included in the full offline suite. A selected synthetic regression can pass independently, but cannot qualify this dataset. No recordings are created or captured automatically.

Prepare at least 20 distinct real camera wave clips and 20 distinct negative clips, with static hands, drawing, phone use and camera movement represented among the negatives. Keep tuning recordings separate. Preserve original recordings privately; export timestamped JPEG sequences without changing their temporal order. Freeze labels, IDs, file hashes and sampling before the scored run. An operator must review labels and establish recording provenance; declaring real media in JSON does not authenticate it. Never duplicate a recording under new IDs to increase sample counts.

Each clip lasts 2–10 seconds and has 11–151 frames. Times start at zero and adjacent samples are 50–200 ms apart (5–20 fps). Include settled pre-roll before the intended wave: the production worker suppresses movement for the first 600 ms. Use image dimensions within the production 1280×1280 total-pixel bound and encoded frames no larger than 1 MiB. The worker applies its normal 640-pixel thumbnail processing. Clips exceeding bounds, invalid images, incomplete processing or hash mismatches cannot count as correct negatives. Paths must resolve inside the manifest directory. The manifest is bounded to 5 MiB and 40–200 clips; frame data is read one bounded file at a time, without retaining all images.

Manifest structure:

```json
{
  "fixture_kind": "real-prerecorded-camera",
  "operator": "human reviewer identifier",
  "frozen_at": "ISO date/time of fixture freeze",
  "human_reviewed_labels": true,
  "clips": [{
    "id": "unique-recording-id",
    "label": "wave",
    "category": "wave",
    "frames": [{
      "file": "clip-id/frame-000.jpg",
      "sha256": "64 lowercase hex characters from the exact image bytes",
      "at_ms": 0
    }]
  }]
}
```

The abbreviated example is not a runnable dataset. Complete every frame and clip. Label values are `wave` and `negative`; categories are `wave`, `static_hand`, `drawing`, `phone_use`, `camera_motion`, or `other`. The wave category must agree with the wave label. Exact duplicate ordered frame/hash sequences and duplicate IDs are rejected. Record corrections to invalid labels transparently and retain the original frozen manifest and failure evidence.

Replay uses the actual production detector worker, verified local MediaPipe model assets, movement settling, detector sampling and PerceptionEvents temporal wave interpretation. Each clip starts with fresh tracking state. The replay clock follows recorded sample times, and every input frame must produce an output. This isolates clip accuracy from live scheduling and latest-frame dropping; it does not qualify physical camera behavior, effective runtime FPS, cloud usage, microphone/audio priority, greeting policy, the 30-minute desk observation, entries, thumb responses or Reachy hardware.

The scorer requires at least 90% recall across wave clips and at most one false wave event across the entire negative set. Multiple events in a single negative count separately. Reports include detected event times, frame counts, detector versions, missed/false-event IDs, counts, recall and manifest hash; image contents stay private. The small-set result is not general accuracy. The live room, natural desk observation, entry and robot gates remain separate required work.

Controlled-entry scorer preparation: live_presence.EntryPlan/EntryDetection/score_entries compare at least ten sustained entry intervals plus startup and occlusion cases. Intervals have source/generation and cannot overlap; observations require explicit greeted status. Exactly one event per controlled entry is required; startup permits one presence event without a greeting, while occlusion must not create a new entry. Duplicate observation IDs, unexpected extra events and wrong sources fail or reject. Physical_qualification remains false: complete observation capture, independent timeline/label/greeting review, bound recordings, natural thirty-minute desk counts and tier entrypoints remain unfinished.

Behavior log continuity is checked by behavior_observation.BehaviorSnapshot and compare_decisions(start, end). Current records retain captured (event clock) separately from at (decision clock). Missing retained rows, owner/order changes, altered overlapping records or conflicting capture/kind identity for the same source/generation/event reject. The result binds snapshot hashes and retains all decisions in the interval. Complete log coverage does not establish detector uptime, physical timing, false-event labels or delivered greeting coverage. Earlier captures without captured metadata do not satisfy this schema. Independent live recording/review binding and natural desk qualification remain required.

Original captured timestamps select case intervals.
