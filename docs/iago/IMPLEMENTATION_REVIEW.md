## Finding: older transcripts could answer during continued speech

A final result for an earlier utterance could clear user-speaking state and start an answer while a newer utterance was being captured, awaiting commit acknowledgment or awaiting its final result. Deterministic ordered-event tests reproduced the issue. Admission now retains both input messages in capture order and waits for pending speech before scheduling the answer. An empty continuation can release an earlier deferred answer; explicit Stop clears that deferral. Epoch validation after transcript delivery prevents a stop/new onset during that await from resurrecting an answer.

This fix does not change Normal/Patient thresholds or make a physical turn-taking claim. Full regression and remaining endpoint tests are tracked separately in PROGRESS.md.
