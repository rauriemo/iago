# Deployment during the active build

The desktop and robot composition paths exist, but V1 is not complete or physically qualified. Consult FEATURES.json and PROGRESS.md for exact gaps. In particular, robot gesture/perception scheduling, complete controls/recovery, playback calibration and mandatory physical gates remain outstanding.

## Native Windows PC

Use Python 3.12 and uv from the repository root. Run `uv sync --locked --group dev --extra vision`, then `uv run --extra vision python -m reachy_brain.vision.detectors --download` to obtain hash-verified perception assets. Keep provider keys and the selected voice in the ignored `.env`. Set `DEPLOYMENT_MODE=desktop`. Enable the optional local perception path with `PERCEPTION_ENABLED=true`.

Launch with `uv run --extra vision iago`. The launcher opens the authorized loopback page. Start requests browser microphone access; camera and screen sharing use their separate controls. No robot packages or daemon are required for this profile. Close the server with Ctrl+C after ending the session.

## Robot-local edge

Run the edge beside an existing Reachy daemon. Install the locked robot dependencies with `uv sync --locked --extra robot`. Configure a private, randomly generated `IAGO_EDGE_TOKEN` of at least 24 characters in the edge process environment or its ignored `.env`. The same token is configured privately in the backend. Do not copy PC provider credentials to an assisted-mode edge; the edge only handles local devices and transport.

Start `uv run --extra robot iago-edge`. The default listener is `127.0.0.1:8877`. The SDK adapter explicitly selects local media and never spawns a simulator or substitutes a PC microphone. For direct LAN access, supply `--host`, `--tls-cert` and `--tls-key`, and configure the backend with the matching HTTPS address and trusted CA file. The client verifies TLS. An SSH local-port tunnel to the loopback listener is another option; then the backend uses the forwarded loopback HTTP address.

The edge has separate control, microphone and snapshot channels. Its local watchdog and VAD can flush playback without receiving a PC response. End/disconnect release SDK media. Actual speaker silence, microphone continuity and motion stopping still require the physical acceptance procedure.

## PC-assisted Reachy

Run the backend on Windows with `DEPLOYMENT_MODE=reachy_pc`, `IAGO_EDGE_URL` set to the reachable edge endpoint, and the private `IAGO_EDGE_TOKEN`. For a private CA, set `IAGO_EDGE_CA_FILE` to its certificate file. Launch `uv run --extra vision iago`. Start the edge first; connection failure is explicit and does not silently start desktop mode.

The backend owns Astra, recognition, synthesis, storage and the robot session. The browser is a control page: it does not acquire the PC microphone in robot profiles. Closing it leaves the robot session active, while clearing sources owned by that page. PC screen sharing still needs an open sharing page, and PC document roots must actually be accessible to the backend.

## Standalone Reachy

Run the same edge locally on the robot, then run the backend there with `DEPLOYMENT_MODE=reachy_local` and the loopback edge address/token. Configure provider credentials privately on that machine. Astra and speech providers remain cloud services; standalone means the PC backend is absent, not local model inference. Access the loopback control page through an appropriate local browser or authenticated tunnel.

PC screens and PC-only folder paths do not become available merely by selecting standalone. A real PC sharing/source session is needed for PC inputs. Onboard package compatibility, camera rate, resource usage and acoustic behavior must be qualified on the target hardware; Windows checks cannot establish ARM or physical performance.

## Verification

For the current comprehensive offline development suite, install both extras and test Chromium, then run `uv run --extra vision --extra robot iago-verify --suite offline --output local-data/evidence/offline`. Provider, live-PC and robot selectors remain separate. Synthetic sources and fake media are explicitly labeled; a passing current subset never promotes an incomplete feature or blocked physical gate.


## Robot camera timing and perception

The edge owns one continuous SDK raw-frame reader capped at 10 Hz. Full-resolution JPEG archive requests run at one-second intervals; independent JPEG previews are limited to 640 pixels for the optional detector worker. Enable `PERCEPTION_ENABLED=true` after installing the vision extra and downloading the pinned models. Neither rate is a physical performance claim.

The current SDK exposes retrieval timestamps without capture PTS. Stored frames identify this limitation. Temporal gestures are suppressed by default on this path. `ROBOT_CAMERA_TIMING_UNCERTAINTY` may hold a measured upper bound in seconds for capture-to-retrieval delay only after target-device qualification; backend clock uncertainty is added to it. An absent bound remains unqualified, and totals above 0.1 seconds cannot associate waves or thumbs. Do not enter zero merely to enable gestures. Full-resolution images and object perception remain available with the timing limitation disclosed.


## Trying a behavior rule

Open **Spontaneous interaction** to edit and save the presets; they start disabled. Enter Aware, enable a camera, select that camera for the next question, enable the desired rule and save. **Run test event (may speak)** injects a clearly labeled synthetic event through the saved rule. It respects disabled rules, quiet hours, source filters and cooldowns. It can invoke configured speech providers when the rule permits a greeting; it does not test the detector or establish physical qualification. Aware prepares the local audio channel but sends cloud microphone audio only after a permitted Conversation activation. An unanswered triggered session returns to Aware after the configured reply window.


The **Reachy camera off/on** button controls the robot camera separately from PC camera and screen-sharing controls. Off clears the robot's visual evidence and stops its archive/detector requests while retaining the conversation mode and independent screen share. It closes the SDK camera pipeline; physical sensor power and daemon-level capture behavior are not established by local fake-media tests. Hardware qualification remains required.


Robot profiles expose **Enable small robot motions** and **Try acknowledgment**. Motion starts disabled. Enabled sessions can make finite listening/speaking cues; Stop invalidates active cues locally. Camera perception receives motion/settling metadata in addition to its image-based suppression. Qualify the small poses, local stop latency and camera behavior on the actual robot before relying on them; offline pose/transport checks do not establish physical safety or acoustic performance.


After an established edge connection is lost, Iago attempts one bounded recovery cycle (three attempts). Successful recovery returns to Idle with motion off and old media/context discarded; choose Aware or Conversation explicitly. **Reconnect robot** retries after exhaustion. End cancels a pending recovery. The implementation does not replay an interrupted answer after reconnection; real network/device recovery timing remains a hardware qualification item.

## Perception model setup failures

Model installation streams into a unique temporary file with the locked byte limit, verifies its SHA-256, then publishes it atomically without overwriting an existing file. Normal failures clean up temporary files. Publication requires a filesystem supporting hard links (tested on this Windows host); unsupported filesystems fail without publishing a partial model. A process crash can leave a `.model-*` temporary file, which is never treated as an installed model.

Diagnostics report `perception_models_missing`, `perception_dependency_missing`, `model_size_mismatch` or `model_hash_mismatch`. Install the vision extra and run the documented model download command for missing assets. Existing corrupt files are deliberately preserved: inspect and move the affected asset aside before retrying. Restart the backend after correcting assets or dependencies. These diagnostics do not establish physical detector accuracy.

Explicit Reindex reparses allowed files even when their content hashes are unchanged, replacing stale failure statuses. If indexing is already active, explicit requests coalesce into one pending full rerun for that project; they are not silently dropped. Original project files remain read-only. A pending rerun is session-local and is canceled at application shutdown.

After the first completed scan, a background scan with no additions, removals or changed file records leaves the database unchanged, including its generation and updated timestamp. Stable exclusions do not cause repeated record replacement. Explicit Reindex still commits a new generation, even for an empty project. The updated timestamp describes the last committed refresh, not the most recent unchanged scan; timing diagnostics still record completed scans. Directory walking and content hashing continue, so this avoids redundant database writes without claiming zero filesystem work or complete idle-resource qualification.

Whole-scan failures appear in project status even when no individual file rows were committed. Status exposes bounded codes such as file_limit, index_capacity, source_unavailable and index_storage_error, without exception text. File-level extraction outcomes remain in the durable coverage records.
